# Topology tooling

Scripts and HTML pages for authoring `*.topology.json` + facility data for new hospitals. The whole flow is designed to take ~one evening per facility, not a development project.

## Where to look

- **Adding a new hospital → [`INSTRUCTIONS.md`](INSTRUCTIONS.md)** — copy-pasteable runbook.

## What's in this folder

| File | Role |
|---|---|
| `fetch_osm_for_facility.py` | Stage 1 — bootstrap building/parking/transit nodes from OpenStreetMap |
| `fetch_departments_for_facility.py` | Stage 2 — extract departments from hospital websites via local LLM |
| `draft_edges_for_facility.py` | Stage 2b — auto-draft edges between nearby nodes, routed via OSM footways |
| `topology_editor.html` | Stage 3 — Leaflet-based editor for nodes + walking-path edges |
| `fetch_aliases_for_facility.py` | Stage 4 — expand each dept's aliases (English + Spanish) via local LLM |
| `build_topology_viewer.py` | Stage 5 — read-only Leaflet viewer over all facilities for sanity-checking |
| `bootstrap/<slug>/` | Per-hospital scratch dir (`osm.json`, `facility.json`, `topology.json`) |
| `topology_viewer.html` | Generated by `build_topology_viewer.py` — don't hand-edit |

## LLM endpoint

`fetch_departments_for_facility.py` and `fetch_aliases_for_facility.py` read `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL` from `training/.env`. Default model: `qwen3.5-122b`. Override per-call with `--base-url` / `--model`.

For reasoning models (qwen3.x etc.) the scripts send `chat_template_kwargs: {enable_thinking: false}` to suppress the `reasoning_content` track. If a server doesn't honor that flag and `content` comes back empty, switch to a non-reasoning model (`gemma4-26b`, `gemma4-31b`, `gpt-oss-120b`).
